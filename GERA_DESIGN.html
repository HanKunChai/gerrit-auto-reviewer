GERA — Gerrit Auto-Review 系统详细设计方案

版本: v6 · 2026-05-13

1. 系统概述

GERA (Gerrit Auto-Review) 是一个面向内网 Gerrit 代码评审平台的自动化代码审查系统。系统持续轮询变更，为每个变更创建独立 git worktree，并行启动 5 个维度专用 Claude Code 进程。Skill 通过 CLAUDE.md 原生加载（非 prompt 嵌入），prompt 仅 ~400B，上下文释放给代码审查。

1.1 设计目标

目标说明
自动化零人工干预，持续轮询 Gerrit 待处理变更并自动提交评审意见
多维度并行5 个 Claude 进程并行评审安全/内存/编码/逻辑/问题评估
Skill 文件夹化5 个维度文件夹，递归加载所有 .md，新增 skill 只需放文件
Skill 原生加载CLAUDE.md 引用 → Claude Code 自动发现，不占 prompt 上下文
并发安全Semaphore 限流 + 命名 ref + worktree 隔离 + lock 保护
内网兼容纯 Python 3.8+，Flask + PyYAML + requests 三依赖
幂等REVIEW_TAG + query -tag 双重过滤，v6 版本标记

1.2 约束

约束值
Python 版本≥ 3.8（目标环境 3.8.10）
第三方依赖flask, pyyaml, requests（仅三包）
AI 评审Claude Code CLI，内网部署
目标代码嵌入式 C 语言（skill 可扩展）
并发模型ThreadPoolExecutor(2) review × ThreadPoolExecutor(5) dimension × Semaphore(4) Claude
评审隔离git worktree detached at local-repo/_review/{id}/{rev}/
输出--output-format json + _extract_review_json 三层提取
评审失败处理超时 / 异常 / returncode≠0 / 空输出 → 跳过提交

3. 数据流详解

3.1 单次评审流程

poll_and_submit()
  ├ Gerrit GET /changes/?q=reviewer:xxx+status:open+-tag:autogenerated:...:v6
  ├ 过滤: 自己的提交 / _in_flight / _already_reviewed
  └ self._executor.submit(_review_task)
       └ _review_change()
            │
            ├ [1] LocalRepo.ensure_branch(base)
            ├ [1] LocalRepo.fetch_change() → refs/review/{id}/{rev} → SHA
            ├ [1] LocalRepo.get_diff(base, SHA, context_lines=3)
            ├ [1] LocalRepo.create_worktree(SHA) → worktree 目录
            │      └ local-repo/_review/{change_id}/{rev_num}/
            ├ [1] 写入 _review_diff.txt 到 worktree
            │
            ├ [2] ReviewEngine.run(diff) → issues（可选，默认关闭）
            │
            ├ [3] _invoke_claude_dimensions()
            │    ├ _ensure_skill_files() → copytree 维度文件夹到 worktree
            │    ├ _generate_claude_md() → worktree 根 CLAUDE.md 引用 skills
            │    ├ ThreadPoolExecutor(5) 并行:
            │    │   ├ _build_dimension_prompt() (~400B, 不含 skill body)
            │    │   │    ├ "请使用 CLAUDE.md 中加载的 skills 进行评审"
            │    │   │    ├ _build_status_table() → 文件变更清单
            │    │   │    ├ needs_context 检测 → 追加上下文指令
            │    │   │    └ JSON schema（verdict 或 issues）
            │    │   └ _invoke_claude(prompt, dimension=dim.name)
            │    │        ├ Semaphore.acquire()
            │    │        ├ claude -p "..." --output-format json --dangerously-skip-permissions
            │    │        ├ timeout / rc≠0 / 空输出 → return None
            │    │        └ Semaphore.release()
            │    └ _extract_review_json() 三层提取
            │
            ├ [4] _build_review_message(dimension_results)
            │    ├ _format_verdict() / _format_issues()
            │    └ 按维度分章节纯文本
            │
            ├ [5] GerritClient.post_review(message, score=0, tag=v6)
            │
            └ 清理: os.remove(_review_diff.txt)
                     repo.remove_worktree()
                     repo.cleanup_review_ref()

3.2 Git 操作并发安全

问题方案
多线程共享 FETCH_HEAD 被覆盖 git fetch gerrit refs/changes/*:refs/review/{id}/{rev} → 返回稳定 SHA
多线程共享 working tree 读到旧版本 create_worktree(SHA) → detached worktree 独立文件系统视图
多线程共用 git config 中的密码 URL _sanitize_url() 日志脱敏，gerrit_push_url 使用 bare URL

3.3 失败处理

路径行为
_invoke_claude 返回 Noneclaude 未找到 / TimeoutExpired / rc≠0 / stdout 为空
多维度路径任一维度失败 → "评审未完成"；全部失败 → 跳过 Gerrit 提交
单维度路径失败 → 跳过 Gerrit 提交

    problem-solving.md

4.2 加载机制

  • _build_skill_registry() 递归扫描 skills/{folder}/**/*.md
  • _ensure_skill_files() 用 shutil.copytree 复制整个文件夹到 worktree
  • _generate_claude_md() 在 worktree 根生成 CLAUDE.md 引用所有 skill
  • Prompt 仅 ~400B：请使用 CLAUDE.md 中加载的 skills 进行评审
  • Skill body 不再嵌入 prompt，上下文释放 ~30KB

4.3 13 个 Skill

文件夹包含 Skillneeds_context
problem-solvingproblem-solving✓
securitybuffer-overflow, injection, unsafe-functions
memoryleak-detection, use-after-free, null-pointer✓
coding-stylebrace-style, line-limit, variable-style
logicbounds-check, return-value, loop-termination✓
needs_context: true → prompt 追加 "发现潜在问题时必须 cat 源文件阅读完整函数上下文后再下结论"

4.4 扩展机制

  • 新增 skill：丢 .md 文件到对应文件夹 → 自动被加载，无需改配置
  • 新增维度：加文件夹 + config.yaml 加一行 {name, folder}

5. 配置

auto_review:
  poll_interval: 600               # 轮询间隔（秒）
  reviewer: "code-reviewer"        # Gerrit reviewer 用户名
  query: "reviewer:code-reviewer+status:open"  # 自动追加 -tag:{REVIEW_TAG}
  max_changes_per_poll: 50         # 每轮最大变更数
  use_rules_engine: false
  max_concurrent_reviews: 2        # review 任务线程池
  max_concurrent_claude: 4         # Claude 子进程 Semaphore
  claude_timeout: 1800             # 单维度超时（秒）
  use_multi_dimension: true
  dimension_timeout: 1800          # 多维度超时（秒）
  dimensions:                      # 维度定义，每个维度一个文件夹
    - name: "问题解决评估"
      folder: "problem-solving"
    - name: "安全"
      folder: "security"
    - name: "内存管理"
      folder: "memory"
    - name: "编码规范"
      folder: "coding-style"
    - name: "逻辑正确性"
      folder: "logic"

6. 并发模型

self._executor (ThreadPoolExecutor, max_workers=2)
  │
  ├ _review_task → _review_change
  │    └ _invoke_claude_dimensions
  │         └ ThreadPoolExecutor(max_workers=5)
  │              ├ _run(安全)       ┤
  │              ├ _run(编码规范)   │
  │              ├ _run(内存管理)   ├ 5 个 _invoke_claude
  │              ├ _run(逻辑)      │   Semaphore(4) 限流
  │              └ _run(问题评估)   ┤
  │
  └ _review_task (第2个review)
       └ ...同上...
层级限制机制
Review 任务2self._executor(max_workers=2)
维度任务5ThreadPoolExecutor(5)
Claude 子进程4threading.Semaphore(4)

8. 安全约束

约束实现
密码不泄露到日志_sanitize_url() 脱敏 3 处日志点
并发隔离命名 ref + worktree + Semaphore
评审失败不泄露失败 → 只写日志，不提交 Gerrit
