# GERA — Gerrit Auto-Review

> 基于 Claude Code CLI / Metis 内网 LLM 的 Gerrit 自动代码评审系统，专为内网嵌入式 C 项目设计。

> **关于本仓库**：这里是对内网部署版本做过去敏处理的公开镜像 —— Gerrit 地址、账号、SVN
> 服务器与本地部署路径均以占位符表示；`.claude/skills/` 评审技能库未包含在仓库中，需按团队
> 规范自行提供。

---

## 项目评估

**GERA 有实际意义**，其核心价值体现在以下几点：

| 价值点 | 说明 |
|--------|------|
| 解决真实痛点 | 代码评审是团队开发的瓶颈之一，自动化初审可以将人工 reviewer 从重复性检查中解放出来 |
| 内网可用 | 仅依赖 `flask`、`pyyaml`、`requests`、`xlrd` 四个包；AI 后端可切换 Claude Code CLI 或 Metis 内网 LLM，**零外网 API 调用**，满足企业内网隔离要求 |
| 双后端可切换 | Claude Code CLI 与 Metis 内网审查器通过 `config.yaml` 的 `use_metis` 一键切换，便于在禁止外网 agent 的环境部署 |
| 确定性流程 + AI 判断 | 约 90% 是确定性代码（轮询 / 过滤 / git / Gerrit API / SVN 合规检查），只有代码语义理解交给 AI |
| 工程质量可靠 | 幂等设计（同一变更同一版本不重复评审）、并发安全（命名 ref + worktree 隔离）、失败静默（AI 评审出错不上报 Gerrit） |
| 可扩展性 | 提示词、规则、Skill 均为外部文件，新增语言或维度只需增加文件与配置 |

**主要局限**：依赖 AI 后端（Claude Code CLI 或 Metis）已安装并完成认证；当前规则和提示词以嵌入式 C 语言为主；评审分数固定为 0（只发表评论，不自动通过/拒绝）；`.claude/skills/` 技能库未随仓库分发。

## 系统架构

```
Gerrit REST API
      │
      ├─── auto_review_poller.py   ← 主入口，持续轮询
      │         │
      │    ThreadPoolExecutor (2 个 review 任务)
      │         │
      │    _review_change()
      │         ├─ GerritClient        → 获取变更信息、提交评审
      │         ├─ LocalRepo           → 独立 git worktree（命名 ref + change 级隔离）
      │         ├─ SVN 合规检查        → 设计文档/自测报告/归档表校验（可选）
      │         ├─ ReviewEngine        → 正则规则匹配（可选）
      │         └─ Claude Code CLI / Metis → AI 语义评审
      │
      └─── mcp_gerrit_server/      ← MCP 服务模式（供 Claude Code MCP 客户端使用）
```

**两种运行模式**（互斥）：

- **轮询模式**：`auto_review_poller.py` 自主运行，定时查询 Gerrit → 评审 → 提交，无需外部触发
- **MCP 服务模式**：`server.py` 作为 MCP Server，由 Claude Code 等客户端主动调用工具执行评审

## 快速开始

### 前置条件

- Python 3.8+
- AI 评审后端二选一：
  - Claude Code CLI（`claude` 命令可用，已登录）
  - Metis 内网 LLM 审查器（`metis` 可执行文件 + `metis.yaml` 配置，见
    [METIS_INTEGRATION.md](METIS_INTEGRATION.md)）
- 可访问的 Gerrit 实例，拥有评审用服务账号
- 可选：`svn` 命令行客户端（仅启用 SVN 提交材料合规检查时需要）

### 安装

```bash
git clone <this-repo>
cd gerrit-auto-reviewer

# 安装依赖
# 方式 1：有外网或内网 PyPI 镜像
bash install.sh

# 方式 2：纯内网无镜像（离线部署）

# 在外网 Linux 机器上先下载依赖
bash scripts/download_deps.sh    # 生成 offline-packages/

# 把整个项目目录（含 offline-packages/）拷到内网机器
# 然后在内网运行
bash install.sh
# install.sh 会自动检测 offline-packages/ 目录进行离线安装。
```

### 配置

编辑 `config.yaml`，最少需要修改以下字段：

```yaml
gerrit:
  base_url: "http://gerrit.your.company.com:8080"
  auth:
    username: "code-reviewer"    # Gerrit 服务账号用户名
# 密码在 .env 文件中设置: GERRIT_PASSWORD=xxx

auto_review:
  reviewer: "code-reviewer"     # 与 username 保持一致
  query: "reviewer:code-reviewer+status:open"
```

选择 AI 后端（二选一）：

```yaml
auto_review:
  use_metis: false            # false = Claude Code CLI（默认）
                              # true  = Metis 内网 LLM 审查器
  metis:
    executable: "<metis-intranet>/venv/Scripts/metis.exe"   # Linux: venv/bin/metis
    config: "<metis-intranet>/config/metis.yaml"
    tiktoken_cache_dir: "<metis-intranet>/tiktoken"
    review_mode: "native"     # native | dimensions
```

编辑 `.env`：

```env
GERRIT_PASSWORD=your_http_password_here
# 启用 SVN 合规检查时（config.yaml 的 svn.enabled=true）：
# SVN_USER=your_svn_user
# SVN_PASSWORD=your_svn_password
```

### 运行

```bash
# 测试连通性（Mock 模式，不连真实 Gerrit）
python scripts/auto_review_poller.py --mock --once --verbose

# 单次执行（连接真实 Gerrit，跑完一轮即退出）
python scripts/auto_review_poller.py --once --verbose

# 持续后台运行（推荐生产使用）
bash run.sh #被动模式

# 启动轮询评审
bash run.sh --poller

# 或只跑一轮测试
bash run.sh --poller --once

# 只评审指定的 Gerrit 变更 URL
python scripts/auto_review_poller.py --url "http://gerrit/c/project/+/12345"

# 或
python scripts/auto_review_poller.py
```

## 评审流程

```
1. 查询 Gerrit: GET /changes/?q=reviewer:code-reviewer+status:open
2. 过滤: 跳过自己的提交 / 已在评审中 / 已评审过当前版本
3. 并发: ThreadPoolExecutor 异步处理（默认 2 个 review 任务）
4. 获取 diff: git fetch refs/changes/{xx}/{id}/{rev} → 本地命名 ref
5. 隔离: 每个 change 创建独立 git worktree，避免多进程读到错误版本
6. SVN 合规: 校验设计文档/自测报告/归档表（可选）
7. 规则引擎: 正则扫描新增行（可配置开关）
8. AI 评审: 多维度并行（Claude Code）或 Metis 原生安全审查
9. 解析: 结构化 JSON / findings → 评审评论
10. 提交评审: POST /changes/{id}/revisions/{rev}/review（score=0，tag 标记版本）
11. 清理: 删除 worktree 与临时 ref
```

**幂等保证**：通过 `autogenerated:gerrit:auto-review:<version>` tag + account_id + revision_number 三要素判断是否已评审，同一 patch set 不会重复提交；版本号在 `config.yaml` 的 `auto_review.reviewer_version` 中配置。

## 规则引擎

内置 17 条 C 语言规则（默认关闭，在 `config.yaml` 中设置 `use_rules_engine: true` 启用）：

| 类别 | 规则数 | 示例 |
|------|--------|------|
| 安全 | 6 条 | `strcpy`/`strcat`/`sprintf`/`gets` 缓冲区溢出，`system()` 注入 |
| 编码规范 | 5 条 | Allman 大括号风格，行长超 200，单行多变量 |
| 常见缺陷 | 6 条 | 空指针解引用，use-after-free，内存泄漏，除零风险 |

**自定义规则**：在 `review_rules/custom/` 目录下添加 YAML 文件，格式参考 `review_rules/builtin/*.yaml`。

## MCP 服务模式

若使用 Claude Code MCP 客户端（而非轮询），启动 MCP Server：

```bash
python -m mcp_gerrit_server.server [--mock] [--verbose]
```

提供 7 个 MCP 工具：`list_changes`、`fetch_diff`、`get_file_context`、`post_review`、`repo_status`、`run_rules`、`c_review_prompt`。

## 配置参考

```yaml
auto_review:
  poll_interval: 600          # 轮询间隔（秒），默认 10 分钟
  max_changes_per_poll: 50    # 每轮最多处理变更数
  use_rules_engine: false     # 是否启用正则规则引擎
  max_concurrent_reviews: 2   # 并发 review 任务数
  max_concurrent_claude: 4    # 全局 AI 子进程上限
  claude_timeout: 1800        # 单个 AI 调用超时（秒）
  reviewer_version: "v6"      # 评审版本，变更后已评审的变更会重新评审
  use_multi_dimension: true   # 多维度并行评审
  use_metis: false            # true=Metis 内网 LLM，false=Claude Code

repo:
  initial_clone_depth: 10     # 首次 clone 深度
  auto_deepen: true           # 遇到 shallow 不足时自动加深

svn:
  enabled: false              # 启用 SVN 提交材料合规检查
  archive_base: "svn://your-svn-host/repo/archive"  # 归档表根路径
  check_commit_material: true # 检查设计文档/checklist/自测报告
  check_realm_archive: true   # 检查问题归档表
  check_requirement_archive: true  # 检查需求归档表

cache:
  ttl_hours: 24               # 评审缓存有效期
```

## 常见问题

**Q: AI 评审失败了怎么办？**  
A: 失败时系统只写日志，不向 Gerrit 上报任何信息，该变更在下一轮轮询时会被重新处理。

**Q: 如何切换 AI 后端？**  
A: 改 `config.yaml` 的 `auto_review.use_metis` 即可：`false` 走 Claude Code CLI，`true` 走 Metis（配置见 [METIS_INTEGRATION.md](METIS_INTEGRATION.md)）。

**Q: 为什么仓库里没有 `.claude/skills/`？**  
A: 技能库与具体团队的内网编码规范相关，未包含在公开镜像中。请按 `config.yaml` 中 `dimensions[].folder` 的目录结构放置对应 skill 文件。

**Q: 如何诊断 Gerrit 认证问题？**  
```bash
python scripts/diagnose_auth.py
```

**Q: 如何只评审某个特定变更？**  
```bash
python scripts/auto_review.py --change-id <change_id>
# 或
python scripts/auto_review_poller.py --url "<gerrit change URL>"
```

**Q: 如何更新评审版本（让已评审的变更重新被评审）？**  
修改 `config.yaml` 中的 `auto_review.reviewer_version`（如 `"v6"` → `"v7"`），重启服务即可。

## 已知限制

- 规则引擎仅支持 C 语言；如需其他语言，需添加对应规则文件和提示词模板
- 评审分数固定为 `0`（不自动给 +1/+2 或 -1/-2）
- 依赖 AI 后端本地安装及登录/部署状态；AI 调用全部失败时跳过上报，等下一轮重试
- SVN 合规检查依赖内部文档模板（设计文档、checklist、自测报告、归档表），需按团队流程调整 `svn.archive_base` 与文档名
- `--dangerously-skip-permissions` 标志适用于内网受控环境，公网部署需评估风险
